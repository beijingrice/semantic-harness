# 标注规范（草稿）

> **状态：草稿。** 本文整理的是现有数据集**实际遵循**的判断习惯，它们原本只零散地写在各条样例的 `why` 里。标有 **⚠ 待定** 的条目，现有标注存在争议或前后不一致，需要项目负责人确定规则后，再统一修改相关样例。
>
> 各数据集的用途和状态见 [examples/DATASETS.md](../examples/DATASETS.md)。

## 总原则

**PASS**：英文和中文的**关键事实**一致，即两个读者分别读完后，会对"要做什么、做到什么程度、在什么条件下、由谁来做"得出相同的结论。

**FAIL**：任何一处关键事实不一致，都判 FAIL，包括：

- 一边有、另一边没有的要求、列举项、例外或条件（**双向检查**：中文多出来的要求同样算 FAIL）；
- 数值、单位换算后的数值、上下界方向或边界开闭不同；
- 义务强度改变（必须 ↔ 可以 ↔ 禁止）；
- 主体、对象、方向或先后顺序互换；
- 例外或条件的适用范围被扩大、缩小或删除。

措辞、句式、语序、段落划分不同，只要关键事实一致，都不影响判断。

## 一、数值与单位

| 规则 | 判断 | 例子 |
|---|---|---|
| 单位换算后数值相同 | PASS | six weeks ↔ 42 天（V2-NUM-03）；72 hours ↔ 连续三天（H28-03）；1.2 cm ↔ 12 mm |
| 数值不同 | FAIL | 95% ↔ 90%（V2-NUM-08） |
| **严格边界与包含边界不同** | **FAIL**，即使是连续量 | below 0.8 mm ↔ 不得超过 0.8 毫米（H28-02）；more than 10% ↔ 10%或以上（V2-NUM-13）；below 25 MB ↔ 可以等于 25 MB（V2-NUM-04） |
| 上下界方向相反 | FAIL | not exceed 30 pages ↔ 不得少于 30 页（C27-06） |
| "以上 / 以下" | 按中文惯例**包含本数** | at least 40 pages ↔ 40页以上：PASS（NUM30-01P） |
| 约数（about、约、左右） | 只和约数比较，不当作精确值 | — |
| 区间两端开闭不清 | 两边同样不清时视为一致 | between 10% and 15% ↔ 百分之十至百分之十五（NUM-03） |

## 二、义务强度（情态）

| 规则 | 判断 | 例子 |
|---|---|---|
| must / shall ↔ 必须 / 须 / 应 / 应当 | 视为同一强度，PASS | must be deleted ↔ 应删除（H28-13） |
| may ↔ must、可选 ↔ 强制 | FAIL | shall ↔ 可以（H28-08）；may invite ↔ 必须邀请（V2-MOD-05） |
| 禁止 ↔ 允许 | FAIL | prohibited ↔ 可以修改（H28-10） |
| 不要求 ↔ 禁止 | FAIL；"不要求"≠"禁止" | not required ↔ 不得添加（P27-12） |
| **should ↔ 须 / 不得** | ⚠ **待定**。现有标注一律按 PASS 处理 | should explain ↔ 须说明（V2-MIX-01）；should not exceed ↔ 不得超过（V2-MIX-07）；should be masked ↔ 须遮蔽（V2-MIX-09） |

> **⚠ should 待定说明**：按 RFC 2119 的惯例，SHOULD（建议）和 MUST（必须）是两种不同的强度。现有数据中，EN 用 should、ZH 用"须/不得"的样例，没有一条标 FAIL。需要确定：should 是否等同于"应/须"？如果不等同，V2-MIX-01、MIX-07、MIX-09、V2-ENU-15 等需要重新标注。

## 三、描述句与规范句

| 规则 | 判断 | 例子 |
|---|---|---|
| 规范类文本中，英文用一般现在时描述（contains、lists、addresses），中文用"应包含/须" | 现有标注视为一致，PASS | contains ↔ 应包含（POL-01、NEW-03）；is submitted separately ↔ 应单独提交（P27-05） |
| 描述内容本身不同 | FAIL | — |

> **⚠ 待定说明**：这条习惯目前只写在 POL-01、NEW-03 的 `why` 里。V2-ENU-13（"The review addresses…" ↔ "综述需要涉及…"）按这条习惯标为 PASS；它在回归集里，曾被模型判为 FAIL。如果决定采用"描述句不等于规范句"，需要重新标注 V2-ENU-11、V2-ENU-13、P27-05、POL-01、NEW-03、NEW-06 等。

## 四、条件与例外

| 规则 | 判断 | 例子 |
|---|---|---|
| 例外被删除、扩大或缩小 | FAIL | unless the program requires it ↔ 无论项目是否另有规定（V2-EXC-03）；仅限摘要的豁免被扩大到正式论文（V2-EXC-08） |
| "只有…才"（必要条件）的保留 | 必须保留，否则 FAIL | only if the supervisor signs ↔ 只有在导师签署后才能（H28-15，PASS） |
| **充分条件 ↔ 必要条件** | ⚠ **待定** | accepted **when** at least 18 are satisfied（充分）↔ 至少满足18项**方可**受理（必要）：现标 PASS（V2-NUM-10） |

> **⚠ 待定说明**：数据集在 only if 上要求严格（H28-15、V2-EXC-06），但 V2-NUM-10 把"满足即接收"和"满足才接收"标为一致。需要确定：日常规范文本中的 when / 方可 是否区分充分与必要条件？

## 五、列举与范围

| 规则 | 判断 | 例子 |
|---|---|---|
| 列举项缺少或多出 | FAIL（双向） | 缺 bounding-box 标注（V2-ENU-02）；多出法语（H28-28）；多出 Markdown（ENU-12） |
| 列举顺序不同 | 不影响；但"顺序不限"被改为固定顺序时 FAIL | V2-ENU-14 |
| 计入 / 不计入（页数、字数限额） | 必须一致 | 封面计入 ↔ 不计入（V2-NUM-15、P27-08） |

## 六、主体、方向与顺序

| 规则 | 判断 | 例子 |
|---|---|---|
| 主体或对象互换 | FAIL | 实验室向医院提供 ↔ 医院向实验室提供（H28-20） |
| 比较方向反转 | FAIL | control > intervention ↔ 干预组高于对照组（H28-24） |
| 比较句换位但方向不变 | PASS | A 高于 B ↔ B 低于 A（DIR-01） |
| 先后顺序反转 | FAIL | 先清洗后计算 ↔ 先计算后清洗（V2-ROL-09） |

## 七、术语与改写的宽严

| 规则 | 判断 | 例子 |
|---|---|---|
| 不同的技术概念 | FAIL | sensitivity ↔ 特异度（AMB-07）；BFS ↔ DFS（TEC-05） |
| 缩写与全称 | PASS | CNN ↔ 卷积神经网络 |
| **近义但范围不同的说法** | ⚠ **待定**。旧开发集按"宽松通过"处理 | data processing ↔ 数据预处理（AMB-03）；methodology ↔ 技术路线（AMB-01）；evaluate performance ↔ 分析实际效果（AMB-04） |

> **⚠ 待定说明**：旧开发集（validation_60、manual_cases）对近义词按 PASS 处理，而新集在数值边界上极其严格（`<0.8` ↔ `≤0.8` 判 FAIL）。需要确定统一的宽严尺度。

## 写 `why` 的要求

- 写清**所有**关键差异，而不只是有意构造的那一处。如果 FAIL 样例的中文是压缩改写，额外省略的内容也要列出。
- 最小差异对的 FAIL 样例，写明与哪条 PASS 样例配对，例如"与 V2-NUM-14（PASS）构成最小差异对：……"。不要写"上一条"，因为文件顺序可能被打乱。
- PASS 样例说明哪些要素对应一致即可。

## 新增样例时的注意事项

- 用自然的中文和英文；不要为了测试解析器硬造句子。
- 构造最小差异对时，尽量让 PASS 和 FAIL 的中文长度相近，避免模型靠"变短了"来猜答案。
- 每个数据集写明状态（开发集、回归集、留出集）。留出集一旦用于调试，就要在 [DATASETS.md](../examples/DATASETS.md) 中注明。
